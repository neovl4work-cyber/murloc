# MURLOC — Local Files plugin for Murglar

Плагин типа `MURGLAR` (`id = "local"`) для музыкального плеера [Murglar](https://github.com/badmannersteam/murglar-plugins),
который отдаёт плееру музыку из локальной папки. Дерево папок на диске отображается в UI Murglar
как «Моя музыка → папки → треки» — свой UI у плагина нет, дерево рендерит хост.

## Структура проекта

Полные заметки по разработке (окружение, сборка SDK, тестирование, устройство кода, риски): [DEVELOPMENT.md](DEVELOPMENT.md).
История создания — от постановки задачи до v1.6, с ошибками и находками: [CREATION.md](CREATION.md).

| Модуль | Назначение |
|---|---|
| `murloc-core` | Реализация плагина; собирается в jar для Murglar Desktop |
| `murloc-android` | Обёртка в apk для Murglar Android + компоненты выбора папки (Activity-пикер и ContentProvider результата) |
| `murloc-cli` | Запуск плагина без хоста: построение дерева, resolveSourceForUrl, скачивание первых байт |
| `test-music/` | Тестовая папка с фейковыми файлами для прогона CLI |

API плагинов: `murglar-gradle-plugin-core/android` **9.0** (jitpack), Kotlin/JDK 17.

## Сборка

```bash
./gradlew :murloc-core:build      # jar: murloc-core/build/libs/murglar-plugin-local-9.9.jar
./gradlew :murloc-android:build   # apk: murloc-android/build/outputs/apk/release/murglar-plugin-local-9.9.apk
./gradlew :murloc-cli:build       # тестовый CLI-модуль
```

Для сборки нужен JDK 17+ (в `PATH` или `JAVA_HOME`). Для сборки apk дополнительно нужны
Android SDK и keystore (см. ниже).

## Установка

**Desktop**: положить `murglar-plugin-local-9.9.jar` в папку плагинов Murglar Desktop
и перезапустить приложение. Папка плагинов — подкаталог `plugins` рядом с исполняемым файлом
Murglar (в зависимости от того, куда установлен плеер; например, при установке в `D:\murglar`
путь будет `D:\murglar\plugins`).

**Android**: установить `murglar-plugin-local-9.9.apk` на устройство — Murglar подхватит её
как плагин (как в документации murglar-plugins).

## Настройки плагина

В настройках сервиса внутри Murglar:

- **Music folders / Папки с музыкой** (`music_dir`) — один или несколько путей
  к папкам с музыкой, разделённых точкой с запятой (`;`). Старая строка с одним путём —
  валидный частный случай. Несколько папок (Desktop): корень «Моя музыка» показывает
  по ноде на каждую папку (при совпадении имён к имени добавляется родительская папка).
  На Desktop это абсолютные пути (по умолчанию `~/Music`). На Android поддерживаются:
  относительные пути (`Music`, `Music/Rock` — на любой памяти), абсолютные пути
  (`/storage/emulated/0/Music`, `/storage/<volume>/<path>` для SD-карт) и SAF tree-ссылки
  (такие же, как у папки загрузчика хоста: `content://...tree/AE7C-9F03:Music/`).
  Фильтр учитывает том MediaStore (`volume_name`), так что `Music` на внутренней памяти
  и на SD-карте различимы при указании полного пути. Пустое значение — вся аудиотека.
  Русские имена и пробелы работают без экранирования.
- **Choose music folder… / Выбрать папку с музыкой…** (`pick_music_dir`) — выбор папок
  через системный диалог: на Desktop — Swing `JFileChooser` (можно несколько), на Android —
  системный выбор папки (`ACTION_OPEN_DOCUMENT_TREE`, см. ниже про устройство apk).
  На Android диалог открывается асинхронно: выбранная папка добавляется к `music_dir`
  при следующем обновлении библиотеки (переход в «Моя музыка»).
- **Playlists folder / Папка плейлистов** (`playlists_dir`, Desktop-only) — папка с
  плейлистами `.m3u`/`.m3u8` (по умолчанию `~/MurglarPlaylists`). На Android плейлисты
  хранятся во внутреннем хранилище приложения хоста (`<filesDir>/murloc-playlists`),
  папки в настройках нет.
- **Open playlists folder / Открыть папку плейлистов** (`open_playlists_dir`, Desktop-only) —
  открывает папку плейлистов в системном файловом менеджере (создаёт её при необходимости).
- **Use embedded stream server / Использовать встроенный сервер** (`stream_server`) —
  если включено (по умолчанию — включено, т.к. гарантированно работает на любой платформе),
  файлы всегда отдаются через встроенный HTTP-сервер (`http://127.0.0.1:<порт>`).
  Если выключено, используется прямой URL (`file://` на Desktop, `content://media/...` на Android),
  а сервер включается автоматически, только если прямой URL недоступен.

## Плейлисты (.m3u)

Чтение API `PlaylistsManager` в API плагинов 9.0 — пустой stub, поэтому создание плейлистов
через UI хоста недоступно. Вместо этого плагин читает плейлисты из файлов:

- «Плейлисты» — отдельный пункт корневого меню сервиса (рядом с «Моя музыка»): все файлы
  `.m3u`/`.m3u8` из папки плейлистов (Desktop — `playlists_dir`, Android — внутреннее
  хранилище приложения хоста) в виде нод-плейлистов.
- Поддерживаются `#EXTINF:<секунды>,<Artist> - <Title>` и пустые `.m3u` со списком путей.
- Пути записей относительны файлу плейлиста (разделители `/` и `\`), несуществующие файлы
  пропускаются, порядок записей сохраняется. Файлы перечитываются при каждом открытии плейлиста.
  На Android записи хранятся как `content://media/...` uri и резолвятся через MediaStore.
- Работают на Desktop и Android одинаково.

## Создание плейлистов из Murglar

Все действия доступны на Desktop и Android из меню нод (кастомные действия плагина):

- **На музыкальной папке** — «Сохранить как плейлист»: создаёт/перезаписывает
  `<playlists_dir>/<имя папки>.m3u` из всех аудио-файлов папки (плоско, без рекурсии).
- **На треке** — по одному действию «Добавить в <имя плейлиста>» на каждый существующий
  плейлист (меню формируется динамически; без дубликатов). Если плейлистов нет — действий
  не показывается.
- **На треке внутри плейлиста** — дополнительно «Удалить из плейлиста»: убирает запись
  из файла `.m3u`, из которого открыт трек.
- **На плейлисте** — «Удалить плейлист»: удаляет файл `.m3u`.
- **На корневом пункте «Плейлисты» и на музыкальных папках** — «Создать плейлист»:
  создаёт пустой `Новый плейлист (yyyy-MM-dd HH-mm).m3u` (на папках — рядом
  с «Сохранить как плейлист»).
- **На корневом пункте «Плейлисты»** — «Открыть папку плейлистов» в системном менеджере
  файлов (Desktop-only).
- **На корневом пункте «Моя музыка»** — «Выбрать папку с музыкой…»: системный диалог
  выбора папки (Swing на Desktop, проводник Android на Android), выбранная папка
  добавляется к `music_dir`.
- **В настройках плагина** — «Создать плейлист»: то же самое из экрана настроек сервиса.
- **Переименование** — в настройках плагина на каждый плейлист есть поле
  «Переименовать "<имя>"» (обычный текстовый ввод настроек). В меню нод переименования нет:
  механика кастомных действий не умеет запрашивать текст у пользователя, а поле ввода
  есть только у настроек сервиса.

## Как это работает

- Логин не требуется: свой `LoginResolver` с `isLogged = true` и пустыми списками вариантов
  логина (в UI кнопки логина не появляются, а ноды остаются доступными).
- Дерево: `BaseNodeResolver` с конфигурациями Root (`myMusic`) + Root (`playlists`)
  + MappedEntity (`*/playlist-<playlistId>`) + Directory (`*/dir-<dir>`)
  + Track (`*/track-<trackId>`). Пути файлов URL-кодируются внутри сегментов путей нод.
- Метаданные: id трека = канонический путь файла (desktop) или `content://media/...` URI (android);
  «Artist - Title» парсится из имени файла, вложенная папка = название альбома;
  длительность — из MediaStore на Android, на Desktop не определяется (`-1`).
- Поддерживаемые расширения: mp3, flac, ogg, m4a, wav, aac, opus, wma.
- Плейлисты и общий код сканеров работают на `java.io.File` (не `java.nio.file`) —
  `java.nio.file` недоступен на Android до API 26, а плагин работает с API 21.
- Выбор папки на Android: код плагина исполняется в процессе хоста без `Context` в API,
  поэтому пикер живёт в самом apk плагина (отдельно установленное приложение с
  собственным манифестом): `FolderPickActivity` показывает `ACTION_OPEN_DOCUMENT_TREE`,
  результат (реальный путь, напр. `/storage/AE7C-9F03/Music`, и исходная SAF-ссылка)
  сохраняется и отдаётся через экспортированный `PickResultProvider`. Core стартует
  активность рефлексией (`AndroidFolderPicker.launchPicker`, асинхронно — не блокирует
  поток хоста) и подхватывает результат одноразовым опросом (`pollPickedFolder`) при
  построении дерева — путь мёржится в `music_dir`, сканер фильтрует по нему MediaStore.
  Persistable uri permission берётся на всякий случай, но для фильтрации нужен только путь.
- Запасной канал воспроизведения — встроенный сервер на NanoHTTPD на `127.0.0.1` со случайным
  портом, стримит файл с поддержкой `Range` (для перемотки). Код плагина исполняется в процессе
  хоста, поэтому INTERNET-permission у хоста уже есть.

## Проверка без хоста (CLI)

CLI инстанцирует `LocalMurglar` с middleware из JSON-файла/preferences, прогоняет:
`getRootNodes` → обход папок `getNodeContent` → список треков → `getTracksByMediaIds` →
`resolveSourceForUrl` → скачивание первых байт по прямому `file://` URL и через StreamServer,
плюс Range-запрос (код 206). Перед запуском в `preferences.json` задайте `"music_dir": "<папка>"`
(по умолчанию используется `~/Music`). В репозитории для этого лежит `test-music/`.

Запуск (fat-jar плагина не содержит kotlin-stdlib — она «provided» со стороны хоста,
поэтому для CLI её нужно добавить в classpath из Gradle-кэша):

```bash
./gradlew :murloc-cli:build
KOTLIN_STDLIB=$(find ~/.gradle/caches/modules-2/files-2.1/org.jetbrains.kotlin/kotlin-stdlib -name "*.jar" ! -name "*sources*" | head -1)
java -cp "murloc-cli/build/libs/murloc-cli-all.jar;$KOTLIN_STDLIB" com.badmanners.murglar.client.cli.MurglarCliKt
```

(на Windows разделитель classpath — `;`, пути — в формате Windows).

## Сборка Android-модуля

Нужны Android SDK и подпись:

1. Установить Android Studio / cmdline-tools → Android SDK.
2. Скопировать `local.template.properties` в `local.properties`, прописать `sdk.dir`
   (модуль `murloc-android` автоматически подключается к сборке, как только `sdk.dir`
   появляется в `local.properties` или в `ANDROID_HOME`/`ANDROID_SDK_ROOT`).
3. Положить keystore в корень проекта (или прописать путь в `local.properties`):
   ```
   storeFile=keystore.jks
   storePassword=...
   keyAlias=release
   keyPassword=...
   ```
   НЕ коммитьте `local.properties` и keystore в репозиторий.
   Если keystore нет — сгенерировать (`keytool -genkeypair ...`) или собрать debug-вариант
   с debug-подписью Android Gradle Plugin.

## Известные ограничения и риски (проверить только на реальном хосте)

- **Приём `file://`/`content://` хостом**: в API `Source.url` заявлены только `http(s)` и `data:`.
  Если Murglar Desktop/Android не умеет играть такие URL напрямую — включите
  «Use embedded stream server», тогда всё пойдёт через `http://127.0.0.1`.
- **Android Context через рефлексию**: `ActivityThread.currentApplication()` — стандартный трюк,
  но на конкретном хосте может не сработать. Тогда плагин покажет пустую библиотеку
  (ошибка будет в логе через LoggerMiddleware). Проверено только компиляцией, не на устройстве.
- **MediaStore на Android**: треки фильтруются по расширению файла; без разрешения хоста
  на чтение медиатеки список будет пуст. `music_dir` фильтрует по `relative_path` —
  внешние SD-карты и USB-накопители отображаются под своим volume id.
- **Пикер папки на Android**: активность apk плагина стартует из процесса хоста — если хост
  блокирует рефлексию к `ActivityThread` или старт активностей из фона, кнопка «Выбрать
  папку…» не сработает (ошибка в логе); ручной ввод пути в `music_dir` работает в любом случае.
  Результат подхватывается при следующем обновлении дерева — если папка сразу не появилась,
  достаточно выйти и зайти заново в «Мою музыку».
- **Кэширование треков** — функция хоста: Murglar кэширует проигрываемое аудио
  (Настройки → Кэш в плеере). API плагинов не даёт пометить трек «не кэшировать»,
  плагин этим не управляет. На Android файлы по умолчанию идут через `http://127.0.0.1`
  (встроенный сервер) и выглядят для хоста как сетевой поток; тоггл «Use embedded stream server»
  отдаёт вместо этого прямой `content://media/...` URL — если хост не кэширует такие
  источники, дубликатов на диске не будет (зависит от хоста, проверяется на устройстве).
- **Длительность треков на Desktop** не определяется (нет парсера тегов) — в UI может
  отображаться неизвестная длительность.
- Desktop-сканер читает только «плоские» файлы в каждой папке (без рекурсивного дублирования
  треков вложенных папок в родительской) — дерево повторяет структуру папок.
