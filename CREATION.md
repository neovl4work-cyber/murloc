# Как создавался MURLOC — история разработки

Этот файл — не техническая документация (она в [README](README.md) и [DEVELOPMENT](DEVELOPMENT.md)),
а рассказ о том, как плагин создавался: от постановки задачи до рабочего релиза, с ошибками и находками.

## Постановка задачи

Нужен плагин типа `MURGLAR` для плеера Murglar, который умеет играть **локальные музыкальные
файлы** — на компьютере и на телефоне. UI должен вписываться в сам Murglar, без отдельного
интерфейса.

Первый шаг — исследование: API плагинов (`badmannersteam/murglar-plugins`) и образцовый плагин
(`murglar-plugin-sample`) были склонированы и изучены. Ключевые выводы, определившие архитектуру:

- Плагин состоит из двух частей: **core** (jar для Desktop) и **android** (apk, который Murglar
  находит по receiver'у в манифесте). Версия API — `9.0`, Kotlin, JDK 17.
- Свой UI у плагина нет: дерево нод, экраны логина и настройки рисует хост. Плагин отдаёт
  данные и описания (`Node`, `Preference`, `Messages`).
- `PlaylistsManager` в API 9.0 — пустая заглушка (`//TODO: implement`): создание плейлистов
  штатными средствами хоста недоступно. Это наложило отпечаток на всю «плейлистную» часть.
- Middleware (настройки, сеть, уведомления, лог) хост передаёт плагину в конструктор.

## Архитектурные решения

**Логин.** Для локального сервиса авторизация не нужна, но нюанс: доступность нод зависит от
`loginResolver.isLogged`, а готовый `NoLoginResolver` возвращает `false` — с ним дерево пустое.
Решение — свой резолвер с `isLogged = true` и пустыми списками вариантов логина: кнопки логина
в UI нет, а ноды доступны.

**Источник аудио — главный риск проекта.** В API `Source.url` заявлены только `http(s)` и `data:`,
поддержка `file://`/`content://` не гарантирована. Поэтому сразу заложено два канала:
прямой URL (`file://` на Desktop, `content://media/...` на Android через MediaStore) и
запасной — встроенный HTTP-сервер на NanoHTTPD (`http://127.0.0.1:<порт>`) с поддержкой Range
для перемотки. Код плагина исполняется в процессе хоста, поэтому сокеты localhost доступны.

**Дерево.** `BaseNodeResolver` с декларативными конфигурациями: Root «Моя музыка» + Directory
для подпапок + Track. Папки на диске = иерархия в плеере. Идентификатор трека — канонический
путь к файлу (URL-кодирован внутри сегментов пути ноды).

**Android-доступ к файлам.** Плагин не получает `Context` через API, поэтому используется
рефлексия `ActivityThread.currentApplication()` и чтение `MediaStore.Audio` через ContentResolver.
На машине разработчика проверяется только компиляцией — работоспособность на устройстве
зависит от хоста.

## Итерации

### v1.0 — первый рабочий плагин
Скелет Gradle-проекта по README репозитория murglar-plugins (jitpack, resolutionStrategy,
murglar-gradle-plugin-core/android 9.0). Реализация: LocalMurglar, LocalNodeResolver,
DesktopScanner (java.nio), AndroidScanner (MediaStore через рефлексию), StreamServer (NanoHTTPD),
LoginResolver, Messages EN/RU, векторная иконка. Плюс модуль `murloc-cli` — адаптация client-cli
из сэмпла для прогона плагина без хоста: дерево → треки → `resolveSourceForUrl` → скачивание
первых байт и Range-запрос.

На машине был только Java 8 — скачан Temurin JDK 17. Сборка и CLI-прогон зелёные с первого раза.
Репозиторий github.com/neovl4work-cyber/murloc, релиз v1.0 с jar.

### v1.1 — находка на живом хосте
Плагин загрузился, дерево построилось, настройки появились — но треки не играли. Причина ровно
та, на которую указывал риск: **Murglar Desktop не принимает `file://`**. Лечится включением
встроенного сервера (тоггл в настройках). Решение: сделать сервер **включённым по умолчанию** —
свежая установка работает сразу. Также выяснилось, где ищет плагины Desktop-хост: подкаталог
`plugins` рядом с исполняемым файлом.

### v1.2 — пикер папок, мульти-пути, плейлисты (.m3u)
Три запрошенные фичи:
- **Диалог выбора папки** — Swing JFileChooser из ActionPreference (с защитой от headless;
  на Android скрыто).
- **Несколько папок** — `music_dir` стал списком через `;`, при >1 корня «Моя музыка» показывает
  по заголовку на каждый корень с разрешением коллизий имён.
- **Плейлисты** — раз `PlaylistsManager` заглушка, сделано через файлы: нода «Плейлисты» показывает
  `.m3u` из настраиваемой папки (по умолчанию `~/MurglarPlaylists`), парсер `#EXTINF` и
  относительных путей. Для сборки apk понадобился Android SDK (cmdline-tools, platform-36,
  build-tools 36.1.0) и keystore — оба не коммитятся.

### v1.3 — «Плейлисты» в корневое меню
Плейлисты переехали из содержимого «Моя музыка» в отдельный Root-узел: слева в меню сервиса
теперь два пункта — «Моя музыка» и «Плейлисты».

### v1.4 — крафт плейлистов из UI Murglar
Проверка API дала механизм `getNodeCustomActions`/`handleEvent` — кастомные действия в меню «⋮»
ноды. Реализовано: «Сохранить как плейлист» на папке, «Добавить в плейлист» на треке
(целевой выбирался в настройках через ListPreference), «Удалить плейлист», «Создать плейлист»
в настройках, «Открыть папку плейлистов».

### v1.5 — переработка контекстного меню
По обратной связи: целевой плейлист из настроек — неудобно. Решение — генерировать пункт меню
**на каждый плейлист** («Добавить в «Вечерний»», «Добавить в «Тренировка»»…), селектор в настройках
убран. Добавлено «Удалить из плейлиста» на треке внутри плейлиста и «Создать плейлист» в меню
корня «Плейлисты» и папок.

### v1.6 — последний штрих
«Выбрать папку с музыкой…» продублировано в меню «⋮» корня «Моя музыка». После этого всё, что
может быть действием над нодой, живёт в контекстном меню; в настройках остались только
свойства сервиса (текстовые пути, тоггл сервера).

### v1.7 — паритет Android
Обратная связь: на Android нет меню действий и плейлистов, выбора папки через проводник
и переименования. Причина была в намеренных Desktop-заглушках (плейлисты жили в файловой
системе, пикер — Swing, а общий код использовал `java.nio.file`, недоступный на Android
до API 26 при minSdk 21). Что сделано:

- **Плейлисты на Android**: хранятся во внутреннем хранилище приложения хоста
  (`<filesDir>/murloc-playlists`, контекст по-прежнему через `ActivityThread`), записи —
  `content://media/...` uri, резолвятся обратно через MediaStore. Корень «Плейлисты» и все
  действия с нодами включены на обеих платформах.
- **PlaylistLibrary переписан на `java.io.File`** вместо `java.nio.file` — единая реализация
  для Desktop и Android API 21+.
- **Пикер папки через проводник Android**: в apk плагина (это отдельное установленное
  приложение со своим манифестом) добавлены `FolderPickActivity` (`ACTION_OPEN_DOCUMENT_TREE`)
  и экспортированный `PickResultProvider`; core стартует активность рефлексией и поллит
  провайдер. Результат конвертируется в реальный путь и мёржится в `music_dir`.
- **`music_dir` на Android наконец работает**: сканер фильтрует MediaStore по `relative_path`
  (принимает относительные и абсолютные пути, пусто — вся библиотека).
- **Переименование плейлистов**: текстовый ввод в кастомных действиях невозможен (API),
  но есть у `EditPreference` — в настройках сервиса генерируется поле
  «Переименовать "<имя>"» на каждый плейлист.
- Поднята версия плагина: 7 → 8.

### v1.9 — фикс SAF-пикера
На устройстве сообщалось о падениях хоста при выборе папки через SAF. Стектрейса не было,
поэтому ANR оставался гипотезой: `AndroidFolderPicker` блокировал поток хоста ожиданием
результата до 90 секунд, а действие могло вызываться на UI-потоке. Плюс фильтр `music_dir`
не учитывал том MediaStore (SD-карта) и не понимал SAF-ссылки. Что сделано:

- **Пикер асинхронный**: `launchPicker` только открывает системный диалог, результат
  подхватывается одноразовым `pollPickedFolder` при построении дерева («Моя музыка») —
  без блокировок и с любого потока хоста.
- **Volume-aware фильтр**: в запрос MediaStore добавлен `volume_name`, корни парсятся
  в (path, volume): относительные пути — на любой памяти, абсолютные — с конкретным томом
  (`/storage/AE7C-9F03/Music` — только эта SD-карта).
- **SAF tree-ссылки**: `music_dir` понимает формат хоста
  (`content://...tree/AE7C-9F03:Music/`), конвертируя его в (volume, path).
- **Юникод и пробелы**: `getTreeDocumentId` возвращает декодированный id — русские имена
  и пробелы проходят без экранирования (раньше тоже работало, теперь зафиксировано).
- В `FolderPickActivity` добавлено `takePersistableUriPermission`, провайдер отдаёт
  исходную SAF-ссылку вместе с путём.
- Поднята версия плагина: 8 → 9.

### v1.10 — прямой доступ к файлам вместо SAF
На устройстве сообщалось о трёх крашах v1.9 за три минуты и неподставленном пути.
Без logcat причина не установлена. SAF-механику в отдельном процессе apk
(`FolderPickActivity` + `PickResultProvider` + запуск из процесса хоста) решили удалить;
по предложению пользователя выполнен переход на **прямой доступ ко всем файлам**:

- **Удалён SAF-пикер целиком** (активность, провайдер, клиент в core, manifest-компоненты).
- **`DirectAndroidScanner`** — обход `/storage/...` обычным `java.io.File`: реальные пути
  треков, папки как на диске, мульти-корни (внутренняя память + тома SD-карт), скрытые
  папки пропускаются. Включается, когда приложению Murglar выдан `MANAGE_EXTERNAL_STORAGE`
  (проверка `Environment.isExternalStorageManager` рефлексией; на API < 30 — по читаемости
  `/storage/emulated/0`). В настройках сервиса — кнопка, открывающая системный экран выдачи
  разрешения именно для пакета хоста.
- **MediaStore-сканер остался запасным** вариантом (без разрешения) — с volume-aware
  фильтром из v1.9. Общий парсер корней `MusicRoots` (относительные/абсолютные пути,
  SAF tree-ссылки → (path, volume)).
- **Выбор папки на Android** — кастомное действие «Использовать как папку с музыкой»
  в меню «⋮» любой папки (без диалогов и сторонних процессов).
- `music_dir` при direct-режиме хранит абсолютные пути; пусто — всё хранилище.
- Поднята версия плагина: 9 → 10.

### v1.11 — ручной ввод и исправление путей Android
После жалобы на неработающий v1.10 код сверен с реализацией выбора папки в FileChat.
Старый SAF-пикер не восстановлен: его activity-result схема требует собственной Activity хоста,
а причина крашей Murloc без logcat не подтверждена. При этом само поле ручного ввода `music_dir`
в v1.10 не удалялось — оно сохранено и теперь проверяется CLI.

- У `music_dir` включено `refreshAllAfterChange`, чтобы Murglar обновлял дерево после смены пути.
- SAF tree URI разбираются с явным UTF-8 percent-decoding, включая кириллицу, пробелы и `+`;
  поддерживаются `primary` и тома SD-карт, отклоняются чужие providers и `..` в пути.
- Для экрана all-files доступа добавлен запасной общий системный intent, как в FileChat.
- Имена корней в общем resolver вычисляются только через `java.io.File` и сам сканер —
  Desktop-only `java.nio.file` больше не вызывается из Android-ветки с несколькими корнями.
- Поднята версия плагина: 10 → 11. Android-поведение требует проверки на устройстве;
  для диагностики оставшихся крашей нужен logcat.

### v1.12 — настоящий SAF без all-files и MediaStore
Пользователь подтвердил, что v1.11 не работает: Murglar отсутствует в системном списке
«Доступ ко всем файлам», а внутренняя память и SD-карта остаются пустыми. Это закрыло
direct/all-files подход. Возвращён системный SAF-проводник, но на этот раз сам грант и все
операции с документами принадлежат apk плагина, а не хосту:

- `FolderPickActivity` открывает `ACTION_OPEN_DOCUMENT_TREE` и сохраняет постоянный read-грант.
- `SafProvider` в процессе apk отдаёт core последний выбор, дерево `DocumentsContract`,
  метаданные и read-only потоки; provider принимает вызовы только от `com.badmanners.murglar`.
- `SafScanner` заменяет и direct-, и MediaStore-сканеры на Android. ID треков и записи
  плейлистов — SAF document URI. Воспроизведение всегда идёт через встроенный HTTP-сервер.
- Ручной ввод `music_dir` сохранён для tree/document URI; декодируются кириллица, пробелы,
  `+` и percent-encoded UTF-8. Поддерживаются внутренняя память и SD-карта через системный picker.
- `MANAGE_EXTERNAL_STORAGE` удалён из манифеста. `DirectAndroidScanner` остался только
  для CLI-проверки на Desktop. Поднята версия плагина: 11 → 12.

Сборка и Desktop CLI проверяют код без Android-хоста. Выбор SAF-папки, provider и
воспроизведение на телефоне требуют отдельной проверки пользователем; без logcat нельзя
заранее гарантировать отсутствие прежних крашей хоста.

## Проблемы и находки по ходу

1. **`file://` не играется хостом** → встроенный сервер по умолчанию (v1.1).
2. **`PlaylistsManager` — заглушка** → плейлисты через .m3u-файлы и кастомные действия.
   Переименование из меню нод невозможно (нет текстового ввода в API) — обход через
   per-playlist EditPreference в настройках (v1.7).
3. **sdkmanager.bat падает из Git Bash** на путях с пробелами/кириллицей → запуск класса
   `SdkManagerCli` напрямую через `java -cp`.
4. **lint кэширует результат и не инвалидируется при изменении `local.properties`** → после
   правок этого файла обязателен `:murloc-android:clean`.
5. **R8 вырезал AWT/Swing**: `java.awt`/`javax.swing` отсутствуют на Android → proguard-правило
   `-dontwarn` в `murloc-android/proguard-rules.pro`, иначе release-сборка падала.
6. **Сломанный raw-строковый литерал** (`"""` с нечётным числом кавычек) «съел» хвост файла —
   компилятор молча игнорировал члены класса. Пойман при рефакторинге PlaylistLibrary.
7. **NanoHTTPD держит не-демон потоки** → в CLI добавлен `System.exit(0)`.
8. **IOException «файл занят другим процессом» в `SdkLocator`** (AGP не мог прочитать
   `sdk.dir` из `local.properties`, Windows) → SDK перенесён в переменные окружения
   `ANDROID_HOME`/`ANDROID_SDK_ROOT`, `sdk.dir` из `local.properties` убран (v1.7).
9. **SAF-пикер в отдельном процессе apk падал на живом хосте** (v1.8–v1.9: краши при
   выборе папки, результат терялся) → механика удалена, на Android прямой доступ
   ко всем файлам (`MANAGE_EXTERNAL_STORAGE`) и выбор папки действием из меню ноды (v1.10).
10. **All-files доступ оказался неприменим к Murglar** (v1.11: приложения нет в системном
    списке, обе памяти пустые) → SAF возвращён в v1.12, но чтение документов вынесено
    в provider apk, который владеет грантом; хост получает только localhost HTTP-поток.

## Как проверялось

Каждая версия: `./gradlew clean build` (3 модуля, включая R8/lint для android) + прогон
`murloc-cli` на `test-music/` — дерево, обход папок, плейлисты, `resolveSourceForUrl`,
скачивание байт по `file://` и через StreamServer, Range-запрос (HTTP 206), с v1.4 — сценарии
кастомных действий. Поведение на живом хосте проверялось вручную на Murglar Desktop
(Windows): загрузка плагина, дерево, настройки, воспроизведение, меню «⋮».

## Итог

Из постановки «проигрывать локальные файлы» вырос плагин, умеющий: мульти-папочную библиотеку,
выбор папок (Swing на Desktop и системный SAF-проводник на Android), воспроизведение через
встроенный сервер, плейлисты .m3u с полным циклом из UI (создать/наполнить/удалить/
переименовать/сохранить папку как плейлист) на Desktop и Android, локализацию EN/RU и
автономный CLI-тест. На Android доступ ограничен выбранными SAF-папками и их постоянными
грантами; кэшированием итогового HTTP-потока по-прежнему управляет Murglar.
